The Constraint

Most AI products assume unlimited bandwidth and average infrastructure. We don't have that luxury.

Building for East African markets means designing for 3G networks, mid-range Android hardware, sign languages and spoken languages with almost no labeled training data, and regulatory systems that change at every border. Cloud-only architectures and off-the-shelf models don't survive those conditions.

So we build the constraint into the architecture from day one: on-device inference where connectivity can't be guaranteed, few-shot models where labeled data doesn't exist yet, and offline-first sync where "always online" isn't a safe assumption.

How We Build

Three architectural decisions, not three slogans.

See the products these decisions built →

Edge-First Inference

Gesture and video processing run on-device, not in the cloud. That's a privacy requirement in NENA's case — no video frames ever leave the phone — and a latency requirement in both products, since round-trips to a server aren't reliable on 3G.

Few-Shot, Low-Resource Learning

Sign languages and many East African languages have almost no annotated training data. We build on few-shot approaches that generalise from a small calibration set, rather than requiring a dataset that doesn't exist yet.

Offline-First Systems

Connectivity drops are the default, not the edge case. Both products queue data locally and sync automatically when a connection returns — no lost records, no manual sync step for the user to remember.
